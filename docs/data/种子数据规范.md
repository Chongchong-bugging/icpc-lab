# 种子数据规范 v1

- **版本**：1.0（G0 基线）
- **适用**：本地开发、测试、演示、生产初始化
- **原则**：可重复执行、幂等、按 `code` 对齐、生产不含演示业务数据、不写入任何真实个人信息

## 1. 数据分层

| 层 | 内容 | dev | test | prod |
|---|---|---|---|---|
| A 参考数据 | 角色、权限、部门、岗位、届次/学期、难度、赛事类型、身份类型、算法大类、规则键 | 必须 | 必须 | 必须 |
| B 系统数据 | 系统管理员账号、内置角色绑定 | 必须 | 必须 | 必须（密码来自环境变量） |
| C 演示数据 | 示例会员、队伍、计划、题目 | 可选 | 按用例 | **禁止** |

- A/B 由 `db/seed/R__seed_reference.sql` 与 `SeedRunner` 保证；C 只在 `dev` profile 且 `app.seed.demo=true` 时执行。
- 生产首次启动必须显式设置 `BOOTSTRAP_ADMIN_PASSWORD`；未设置则拒绝启动（fail fast），不生成默认弱密码。

## 2. 幂等与标识

1. 参考数据一律有稳定 `code`（大写下划线），以 `code` 为幂等键；UUID 用固定常量，保证跨环境一致。
2. 插入用 `INSERT ... ON CONFLICT (code) DO UPDATE SET name=..., updated_at=...`；**不删除**已有行。
3. 只增不删：停用用 `status=DISABLED`；合并用 `merged_into_id`。
4. 每次执行输出 `inserted/updated/skipped` 计数；重复执行必须 `inserted=0`。
5. 种子不依赖自增序列；时间戳用固定值（如 `2026-09-01T00:00:00Z`），避免每次 diff。

## 5. 执行与校验

1. 启动顺序：Flyway 结构迁移 → A/B 种子 → 可选 C 演示数据。
2. 种子执行结果写入 `seed_run`（批次、文件、计数、耗时、校验和）。
3. 校验断言：
   - 角色 11、权限点与枚举一致、部门/岗位 code 唯一；
   - 10 个算法大类存在且 `parent_id is null`；
   - 未确认规则 `value is null and mode='MANUAL'`；
   - 重复执行 `inserted=0`；
   - 生产环境不存在 `seed_batch like 'dev-%'` 的行。
4. CI 用 Testcontainers 跑两次种子，第二次必须无插入、无更新、无异常。
