# 权限矩阵 v1（RBAC + 数据范围）

- **版本**：1.0（G0 基线，随 P0-04 实现同步修订）
- **权威**：GOV-001 DOM-20..23、NFR-02/03、FR-01、规格 2.1/7.2
- **实现**：Spring Security 方法级鉴权 + 服务层数据范围校验；前端只做展示，不作为安全边界

## 1. 角色

| code | 名称 | 说明 |
|---|---|---|
| `APPLICANT` | 申请人 | 未入会或申请中；仅本人申请与公开信息 |
| `MEMBER` | 普通会员/竞赛队员 | 正式或备选会员的基础角色 |
| `TEAM_MEMBER` | 集训队队员 | 培养身份，叠加在 `MEMBER` 上（Q-03） |
| `CAPTAIN` | 队长 | 队伍范围角色，由队伍关系派生，不自动获得系统管理权限 |
| `MENTOR` | 导师/助理教练 | 带教范围；可记录训练与反馈 |
| `MINISTER` | 部长/副部长 | 部门范围管理；竞赛部/办公室按部门区分 |
| `PRESIDENT` | 会长/分管副会长 | 全局业务管理；综合管理类审批 |
| `COUNCIL` | 理事会 | 审议与表决；只读 + 特定决议 |
| `ADVISOR` | 指导老师 | 全局只读 + 关键审批；不参与日常录入 |
| `OFFICE` | 办公室 | 行政/财务/资产（P2 前仅行政） |
| `SYSADMIN` | 系统管理员 | 账号、角色、配置、审计；**不得替业务角色做审批** |

> 判定顺序：认证 → 角色权限点 → 数据范围 → 业务状态守卫（如"仅待审批可批"）。任一失败返回 403，不泄露对象是否存在。

## 2. 数据范围

| scope | 含义 | 典型持有者 |
|---|---|---|
| `SELF` | 仅本人数据 | 所有登录用户 |
| `TEAM` | 本人所在队伍 | `CAPTAIN`、`TEAM_MEMBER` |
| `DEPARTMENT` | 指定部门（含下级） | `MINISTER`、`MENTOR`（带教组） |
| `GLOBAL` | 全实验室 | `PRESIDENT`、`ADVISOR`、`SYSADMIN` |

- `role_assignment` 记录 `scope_type/scope_id`；`GLOBAL` 时 `scope_id=null`。
- 同一用户多角色取**并集**；写操作取**最宽命中**但受状态机限制。
- 离任/到期：`role_assignment` 失效 → 下一次请求即拒绝（`token_version` 递增，会话立即失效）。

| 报表 | `report:read` `report:read:scoped` | 聚合数据 |

| 审计 | `audit:read` | 只读，不可改 |
| 附件 | `file:upload` `file:download` | 上传本人材料 / 按范围下载（短时签名链接） |
| 系统 | `system:config` `job:run` | 管理员 |

## 5. 关键约束

1. **禁自批**：审批步骤的 `approver_id` 不得等于申请人/发起人；系统管理员代批一律拒绝（I-07）。
2. **审批 ≠ 生效**：审批通过只写决策；生效由业务服务按 `effective_at` 执行，二者分开审计（D-05）。
3. **导出单独授权**：`export:request` ≠ `export:download`；下载链接短时有效、绑定用户与行数上限（DATA-12）。
4. **队长不是系统角色**：`CAPTAIN` 仅授予 `TEAM` 范围，可管本队报名/任务，不可读他队档案（AT-11）。
5. **理事会是只读 + 决议**：不直接改业务数据；决议通过审批/会议记录落地（FR-34，P2）。
6. **办公室不碰竞赛业务**：行政/财务/资产（P2）之外只读（P2 前仅行政）。
7. **指导老师只读 + 关键审批**：可审批计划/退出/选拔结果，不代录考勤、不改成绩（AT-11 反向用例）。
8. **系统管理员不参与业务决策**：可配置与排障；需要业务决定时转交对应角色，操作留审计。
9. **停用即失效**：账号 `status=DISABLED` 或 `token_version` 变更后，已签发 token 立即失效（NFR-02）。
10. **默认拒绝**：未在矩阵声明的权限点一律拒绝；新增权限点必须同时更新本表与 `PermissionCode` 枚举及测试。

## 6. 校验点（实现时）

- 控制器：`@PreAuthorize("hasAuthority('member:read')")`。
- 服务：`ScopeGuard.require(action, target)` 校验 `SELF/TEAM/DEPARTMENT/GLOBAL` 与对象归属。
- 查询：所有列表接口强制注入范围条件，禁止"先全查再过滤"。
- 测试：每个权限点至少 1 正 1 反；AT-11 覆盖越权读取/下载/自批。
